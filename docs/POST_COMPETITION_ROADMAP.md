# SkillPass 后续开发路线图

状态：后续开发基线

上位文档：

- `COMPETITION_DEMO_V1.md`
- `KEY_CUSTODY_NETWORK_V1.md`
- `KEY_CUSTODY_PARAMETERS_V1.md`

---

## 一、原则

比赛版先完成“使用到拥有”的完整闭环。开放密钥网络、多代币质押和复杂经济机制在
比赛后分阶段开发，不能阻塞比赛交付。

```text
先证明产品闭环
-> 再证明自动交付
-> 再开放节点
-> 最后做经济网络
```

## 二、阶段总览

```text
Phase 0  比赛闭环
Phase 1  Ownership Sale 产品化
Phase 2  独立 2-of-3 启动网络
Phase 3  多代币质押测试网
Phase 4  6-of-9 / 8-of-11 生产委员会
Phase 5  奖励、惩罚、保险和治理
Phase 6  所有权二级转让和开放市场
```

## 三、Phase 0：比赛闭环

目标：

```text
一个统一网站
一个 Research-to-Story
一次使用
一次买断
一次 2-of-3 自动交付
```

交付：

- 统一网站信息架构；
- Ownership Exchange 页面；
- 本地或测试链 Ownership Sale；
- 三个演示节点；
- 自动付款监听；
- 加密文件份额交付；
- 浏览器本地重建密钥；
- 公开验证页；
- 演示视频和评委指南。

完成标准：

- `COMPETITION_DEMO_V1.md` 的十项验收全部通过；
- 原有提交证据不被破坏；
- 演示明确区分真实和模拟部分。

## 四、Phase 1：Ownership Sale 产品化

目标：

```text
把比赛演示变成真实可用的站内买断产品
```

范围：

- 正式 Ownership Sale 合约；
- Trust Registry 按 Passport 限定转移权限；
- 资产版本和 Manifest；
- 买方公钥注册；
- 自动付款确认；
- 幂等订单；
- 自动退款；
- Ownership Receipt；
- 管理界面中的订单、交付和异常状态。

安全：

- 合约审计；
- 重放和重复结算测试；
- 链重组测试；
- 故障恢复；
- 争议处理流程。

## 五、Phase 2：独立 2-of-3 启动网络

目标：

```text
从三个 IMOO 节点迁移为三个独立控制方
```

建议控制方：

```text
IMOO
IGNIX
OKX 或第三方独立运营方
```

范围：

- 节点注册表；
- 节点签名身份；
- KMS/HSM；
- 份额初始化；
- 独立订单验证；
- 节点交付证明；
- 节点离线处理；
- 份额重分发；
- 密钥纪元。

完成标准：

- 任一节点离线仍可交付；
- 任一单节点无法恢复完整密钥；
- 三个控制方具有独立管理员和密钥权限；
- 节点迁移不改变买方体验。

## 六、Phase 3：多代币质押测试网

目标：

```text
验证项目方代币、折扣、价格预言机和权重上限
```

范围：

- Token Registry；
- A/B/C/D 风险层级；
- 多代币 Stake Position；
- 有效质押计算；
- 预言机和价格异常；
- 单运营方权重上限；
- 单代币和发行方集团上限；
- 补仓和降权；
- 解除质押。

测试网验证：

- 至少三种测试代币；
- 项目币暴跌；
- 预言机失效；
- 关联代币；
- 单运营方大量注册；
- 多签名运营方。

完成标准：

- 任意项目币不能替代基础安全质押；
- 单一运营方不能靠多币种绕过权重上限；
- 价格异常时权重只能降低或冻结。

## 七、Phase 4：生产委员会

目标：

```text
从 2-of-3 升级为 6-of-9 和 8-of-11
```

范围：

- 随机委员会选择；
- 运营方去重；
- 候选和候补节点；
- 资产风险分级；
- 100% 经济覆盖；
- 高价值资产专用节点；
- 密钥份额重分发；
- 新节点加入和旧节点退出；
- 多区域和独立 RPC。

完成标准：

- 标准资产使用 `6-of-9`；
- 高价值资产使用 `8-of-11`；
- 联盟控制超过 10% 后触发额外风控；
- 高价值资产的单节点质押满足覆盖率；
- 节点故障和退出不阻断正常交付。

## 八、Phase 5：奖励、惩罚、保险和治理

目标：

```text
让节点围绕真实服务持续运营
```

范围：

- 参与交付奖励；
- 候补和在线奖励；
- 持续存储基金；
- 协议基金；
- 可证明违规罚没；
- 申诉和复核；
- 保险池；
- 参数治理；
- 时间锁；
- 紧急暂停。

安全限制：

- 无法证明的密钥复制不能假装被自动惩罚；
- 保险不能替代密钥迁移；
- 单一管理员不能任意罚没；
- 治理不能直接读取节点份额。

## 九、Phase 6：二级转让和开放市场

目标：

```text
让所有权在不依赖原所有者在线的情况下再次转让
```

前提：

- 托管网络持有足额份额；
- Ownership Sale 支持再转让；
- 版权和商业权利规则明确；
- 旧所有者已知内容无法被撤回的事实已公开；
- 二级市场不复制 OKX.AI 的通用服务市场。

范围：

- 二级 Ownership Order；
- 版税和 Creator Proof；
- 转让历史；
- 买方公钥轮换；
- 版本更新权利；
- 争议和冻结。

## 十、长期基础设施

后续可能增加：

- 多链密钥份额；
- DeWEB 作为主交付通道；
- 普通钱包与容器双通道；
- 阈值签名和门限解密升级；
- 可信执行环境；
- 零知识份额正确性证明；
- 节点软件开源和可复现构建；
- 独立安全审计；
- 多司法辖区合规；
- 内容和版权合规模块。

## 十一、永远不做

- 在链上保存明文密钥；
- 让单个服务器保存所有明文内容密钥；
- 用质押伪造绝对安全；
- 让买方在正常流程中手动确认付款后的交付；
- 把 OKX.AI Service Order 当作资产所有权买断；
- 把比赛演示包装成已经完成的开放网络；
- 在没有审计和保险时承诺高价值资产绝对安全。

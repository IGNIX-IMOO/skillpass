# ADR 0007：统一比赛演示范围

状态：已接受

日期：2026-09-24

相关文档：

## 背景

SkillPass 的完整设计已经扩展到许可证、服务调用、资产买断、阈值密钥托管、多代币
质押、节点委员会、奖励、惩罚、保险和治理。

这足以形成长期基础设施，但超出了比赛演示需要的范围。继续把全部功能塞进比赛会
增加失败风险，并模糊产品主线。

## 决定

1. 比赛只展示一条统一闭环：

```text
使用 Skill
-> Receipt
-> 买断 Skill
-> 2-of-3 自动交付
-> 拥有 Skill
```

2. 比赛使用一个统一网站、一个技能和一套叙事。
3. 比赛复用现有 Processor、Skill Gate、License Quota、Trust Registry 和 Container。
4. 比赛新增站内 Ownership Sale、三个演示节点和自动份额交付。
5. 比赛使用 `2-of-3`，不使用 `6-of-9` 或 `8-of-11`。
6. 多代币质押、委员会、奖励、惩罚、保险和治理进入后续路线图。
7. 真实链上证据和比赛演示功能必须在网站上分开标记。
8. 后续高级网络不能阻塞比赛闭环。

## 结果

正面：

- 比赛目标清晰；
- 网站叙事完整；
- 产品闭环可以被真实操作；
- 高级网络仍然保留长期方向；
- 实现范围和风险可控。

负面：

- 比赛不会展示开放质押网络；
- 三个演示节点不是最终去中心化形态；
- 多代币经济需要比赛后继续验证；
- 部分功能只能作为路线图展示。

## 拒绝的方案

### 把完整密钥托管网络一起做进比赛

拒绝。范围过大，安全验证不足，会阻塞“使用到拥有”的完整闭环。

### 只做许可证项目

拒绝。缺少最有差异化的资产买断和自动交付。

### 只做买断演示

拒绝。缺少真实使用、Receipt 和商业价值证明。

### 把高级网络包装成已完成

拒绝。会误导评委、用户和节点运营方。
